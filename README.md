# Intelligent ETA Predictor

A full-stack Machine Learning application that predicts real-time food delivery ETAs. This project uses a **Multi-Input Multi-Output (MIMO) Neural Network** to simultaneously predict kitchen preparation time and rider travel time based on dynamic logistics parameters like weather, traffic density, and vehicle type.

## 🛠️ Tech Stack
*   **Machine Learning:** Python, TensorFlow / Keras, Scikit-Learn, Pandas
*   **Backend:** FastAPI, Uvicorn, Pydantic, Joblib
*   **Frontend:** HTML5, Tailwind CSS, Vanilla JavaScript (Fetch API)

## Model Architecture
The core is a Custom MIMO Neural Network:
*   **Inputs:** 18 features (Age, Rating, Distance, One-Hot Encoded Weather, Traffic, City, and Vehicle Types).
*   **Shared Trunk:** Dense hidden layers that learn the underlying friction of urban logistics.
*   **Branched Outputs:** Two separate linear output nodes for `prep_time` and `travel_time`.

## Blockers & Engineering Fixes

During the transition from Jupyter Notebook to a production FastAPI server, several critical data pipeline issues were identified and resolved:

*   **Blocker: The Shape Mismatch Error (One-Hot Encoding Trap)**
    *   *Issue:* The FastAPI request only sent 8 features, but the Scikit-Learn scaler expected the 18 features generated by `pd.get_dummies()` during training.
    *   *Fix:* Exported the exact `EXPECTED_COLUMNS` array from the Jupyter Notebook using `joblib`. The API now dynamically builds a zero-filled Pandas DataFrame template matching this exact shape before injecting the user's API data.
*   **Blocker: The "Silent Pandas" Filter Trap**
    *   *Issue:* Pandas `select_dtypes(include=['number'])` silently deleted all one-hot encoded Booleans (True/False) and the `Age`/`Rating` columns (which were classified as text/objects due to raw `"NaN "` strings in the Kaggle CSV).
    *   *Fix:* Used `pd.to_numeric(errors='coerce')` to clean the Age and Rating columns first, and updated the filter to `select_dtypes(include=['number', 'bool'])` so the model could actually learn from weather, traffic, and driver metrics.
*   **Blocker: Dirty String Matching (The "conditions Sunny" Bug)**
    *   *Issue:* The frontend was sending `"Sunny"` or `"Jam"`, but the model ignored them because the Kaggle data formatted them as `"conditions Sunny"` or `"Jam "` (with trailing spaces). Exact dictionary key lookups were failing silently.
    *   *Fix:* Replaced exact matching with a bulletproof substring loop in FastAPI (`if cat.lower() in col.lower():`) to reliably map incoming JSON values to the dirty column names.
*   **Blocker: Extrapolation & Edge Case Bias**
    *   *Issue:* The model predicted that a bicycle would be faster than a motorcycle on a 12.5 km trip in a traffic jam (because bicycles bypass traffic in the training data, but Delivery app never assigns bicycles to 12.5 km routes).
    *   *Fix:* Identified the limits of ML extrapolation and the necessity of implementing **Business Logic Guardrails** (e.g., restricting bicycle selections to < 3km routes) in the production API layer.

## How to Run Locally

**1. Start the FastAPI Backend**
```bash
# Install dependencies
pip install fastapi uvicorn pandas scikit-learn tensorflow joblib pydantic

# Run the server
uvicorn main:app --reload
```


The API will be available at http://127.0.0.1:8000. You can view the auto-generated Swagger documentation at /docs.

**2. Start the Frontend**

Open index.html in any modern web browser.

Adjust the logistics sliders and click "Calculate Live ETA" to fetch predictions from the local API.
